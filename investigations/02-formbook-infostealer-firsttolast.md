## 1. Executive Summary

On August 9, 2026, network traffic analysis within the enterprise domain `FIRSTTOLAST.TECH` revealed an active infection by the **FormBook** infostealer on host `172.16.8.49`. 

Following initial compromise, the infected workstation initiated continuous, unencrypted HTTP GET beaconing sessions across multiple public IP addresses (including `172.64.155.76`, `146.59.71.167`, `38.182.168.246`, and `45.130.41.161`). These requests exhibited FormBook's signature behavioral pattern: uniform 4-character root URI directories (such as `/ujvq/`, `/irpw/`, `/lqjm/`, `/rd80/`) appended with heavily obfuscated parameter strings. Forensics parsing of Kerberos authentication tickets and DCE/RPC SAMR exchanges identified the affected workstation as `DESKTOP-5NLV63K` operated by user `rvance` (Raymond Vance).

## 4. Analytical Phase Breakdown & Commands

### Phase 1: Triage and Subnet Scoping with Zeek

#### A. Initial Subnet Connection Profiling
Processed the capture offline and inspected internal flows from subnet `172.16.8.0/24`, filtering out the Domain Controller (`172.16.8.2`):
```bash
zeek -C -r /path/to/2026-08-09-traffic-analysis-exercise.pcap
zeek-cut id.orig_h id.resp_h id.resp_p proto < conn.log | grep "^172\.16\.8\." | grep -v "172\.16\.8\.2" | head -n 25

```

* **Observation:** Detected outbound connections from `172.16.8.53` towards public IP `23.33.85.235:80`.



#### B. Eliminating Legitimate OS Noise (NCSI False Positive)

Investigated the URI requests originating from `172.16.8.53`:

```bash
zeek-cut id.orig_h id.resp_h host uri < http.log | grep "23\.33\.85\.235"

```

* **Finding:** The request targeted `www.msftconnecttest.com/connecttest.txt`. This was confirmed as legitimate Windows Network Connectivity Status Indicator (NCSI) activity and discarded.



#### C. Isolating FormBook C2 / Decoy Beaconing

Suppressed standard operating system background noise across the entire HTTP dataset:

```bash
zeek-cut id.orig_h id.resp_h host uri < http.log | grep -v "msftconnecttest" | grep -v "windowsupdate"

```

* **Finding:** Uncovered a dense flood of anomalous HTTP GET requests generated by `172.16.8.49` targeting diverse external IP addresses with 4-character root directories (`/ujvq/`, `/irpw/`, `/lqjm/`, `/rd80/`) and long obfuscated strings (`?2kn1=...&kbBSJ=...`).


* **Triage Conclusion:** The compromised host was isolated as **`172.16.8.49`**.



#### D. Active Directory Account Correlation

Parsed Kerberos ticket transactions for `172.16.8.49` to isolate identity markers:

```bash
zeek-cut id.orig_h client < kerberos.log | grep "172\.16\.8\.49" | sort -u

```

* **Host Machine Principal:** `DESKTOP-5NLV63K$`

* **User Principal:** `rvance`

* **Enterprise Realm:** `FIRSTTOLAST.TECH`

### Phase 2: Deep Packet Dissection with Wireshark & Tshark

#### A. Physical MAC Address Extraction

Filtered frames emitted by the confirmed victim IP:

```text
ip.src == 172.16.8.49

```

* Selecting an outbound frame and expanding the **Ethernet II** header revealed the hardware address in the `Source` field:


* **MAC Address:** `00:12:f0:28:d4:34` (`Intel_28:d4:34`).


* *(Note: Multicast destination `01:00:5e:00:00:16` was excluded)*.





#### B. Full Legal Name Extraction via SAMR (Headless CLI Parsing)

When LDAP display name attributes are not transmitted in cleartext, the Security Account Manager Remote (SAMR) DCE/RPC interface exposes user metadata:

```bash
tshark -r /path/to/2026-08-09-traffic-analysis-exercise.pcap \
  -Y "samr.samr_UserInfo21.full_name" \
  -T fields -e samr.samr_UserInfo21.full_name | sort -u

```

* **Command Breakdown:**
* `-Y "samr.samr_UserInfo21.full_name"`: Evaluates RPC account management structures.


* `-T fields -e samr.samr_UserInfo21.full_name`: Prints the decoded Unicode string value directly.




* **Result:** Returned `Margaret Hanson` and `Raymond Vance`. Correlating against the active Kerberos user account `rvance` confirmed the victim's identity as **Raymond Vance**.
